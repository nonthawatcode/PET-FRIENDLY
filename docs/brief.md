# Project Brief — Marketplace Order & Inventory Web App
**เวอร์ชันย่อสำหรับ Claude | เน้นใช้งานง่าย แต่รายละเอียดงานครบ**

## 1. เป้าหมายและขอบเขต
สร้าง **เว็บหลังบ้านของร้านค้าออนไลน์ในประเทศไทย** โดยให้ Claude ช่วยออกแบบและพัฒนาเว็บขึ้นเอง ไม่ใช้ระบบสำเร็จรูปเป็นระบบหลัก ปัจจุบันอยู่ในช่วงวางแผนก่อนเปิดร้าน

- ช่องทางขายเป้าหมาย: **Shopee, Lazada, TikTok Shop**
- เว็บนี้ใช้ภายในร้าน **ไม่ใช่เว็บไซต์ขายสินค้าหรือ POS หน้าร้าน**
- จุดประสงค์: รวมออเดอร์ เก็บข้อมูลที่จำเป็นของลูกค้า ตรวจสินค้า/แพ็กพัสดุ และจัดการสต็อกในที่เดียว
- ค้นย้อนหลังได้ว่า **ออเดอร์ไหน มาจากแพลตฟอร์มใด ใครเป็นผู้สั่ง/ผู้รับ สั่ง SKU อะไร จำนวนเท่าไร และดำเนินการถึงขั้นตอนไหน**
- ใช้เครื่องสแกนบาร์โค้ดแบบมือถือสำหรับใบปะหน้า และอาจใช้สแกน Data Matrix บนสินค้า

**หลักการออกแบบ:** เมนูน้อย เข้าใจง่าย แต่เก็บรายละเอียดและประวัติอย่างถูกต้อง ไม่เพิ่มเมนูหรือฟังก์ชันนอกบรีฟโดยไม่ถามก่อน

## 2. โครงสร้างเว็บ: 3 เมนูหลัก + Settings

### A. Overview
หน้าแรกสรุปข้อมูลสำคัญโดยไม่ต้องมีเมนู Reports แยก
- ยอดขายและจำนวนออเดอร์จากข้อมูลที่ระบบรับมาได้จริง
- สถานะออเดอร์: รอแพ็ก / กำลังแพ็ก / แพ็กแล้ว / จัดส่งแล้ว / ยกเลิก (แยกสถานะภายในกับสถานะ Marketplace ตามความจำเป็น)
- รายการที่รอดำเนินการและสินค้าใกล้หมด
- ดูประวัติการทำงาน/รายการล่าสุดแบบย่อ และกดดูรายละเอียดได้
- เลือกช่วงวันที่และกรองแพลตฟอร์มได้

**ไม่ต้องมี:** กราฟวิเคราะห์ซับซ้อน สินค้าขายดี หรือรายงานธุรกิจเชิงลึกในเวอร์ชันแรก

### B. Products & Inventory
รวมการจัดการสินค้าและสต็อกไว้ในหน้าเดียว
- สร้าง/แก้ไขสินค้า: ชื่อสินค้า, SKU, กลิ่น/ขนาดหรือตัวเลือกสินค้า, รูปสินค้า (ถ้ามี)
- เชื่อม **SKU ภายใน** กับ SKU/รหัสตัวเลือกของแต่ละ Marketplace
- จัดทำและผูก **Data Matrix** กับ SKU สำหรับงานภายใน
- ดูสต็อกแยกเป็น **ของในคลัง (On-hand), ยอดจอง (Reserved), พร้อมขาย (Available)**
- รับสินค้าเข้า ปรับยอด ดูประวัติการเพิ่ม/ลดสต็อก พร้อมเวลาและเหตุผล
- แจ้งเตือนเมื่อสินค้าใกล้หมด

**ยังไม่ทำในเวอร์ชันแรก:** การจัดการล็อตผลิต วันหมดอายุ และการติดตามสินค้าเป็นรายชิ้น เว้นแต่ยืนยันความจำเป็นภายหลัง

### C. Orders & Fulfillment
รวมออเดอร์ แพ็กสินค้า และจัดส่งไว้ในเมนูเดียว
- ตารางออเดอร์รวมจากทุกช่องทาง พร้อมค้นหา กรองแพลตฟอร์มและสถานะ
- รายละเอียดแต่ละออเดอร์: แพลตฟอร์ม, เลขออเดอร์, วัน/เวลา, ชื่อผู้ซื้อหรือผู้รับที่เข้าถึงได้อย่างถูกต้อง, รายการสินค้า/SKU, จำนวน, ยอดออเดอร์ถ้ามีสิทธิ์, สถานะ, เลขพัสดุ
- รองรับการดู/พิมพ์ **ใบปะหน้าที่ได้รับจากช่องทางที่อนุญาต** ไม่สร้างใบปะหน้าขนส่งหรือเลขพัสดุขึ้นเอง
- สแกน **บาร์โค้ดบนใบปะหน้า** เพื่อค้นหาและเปิดออเดอร์ที่ผูกกันไว้
- แสดงรายการสินค้าที่ต้องหยิบ/แพ็ก และให้ตรวจสอบความถูกต้อง (รองรับการสแกน Data Matrix ของสินค้า หากเลือกใช้)
- กด **ยืนยันแพ็ก** เพื่อบันทึกผลและตัดสต็อกตามกติกา
- รองรับออเดอร์ยกเลิก งานแพ็กผิดพลาด และการคืนสินค้าโดยไม่ปรับสต็อกผิด
- ดูประวัติออเดอร์: การรับออเดอร์ การแพ็ก การตัด/คืนสต็อก และข้อมูลขนส่งที่ได้รับจริง

### Settings (ไอคอนมุมบน ไม่ต้องเป็นเมนูหลัก)
- เชื่อมต่อ/ดูสถานะบัญชี Shopee, Lazada, TikTok Shop เมื่อมีสิทธิ์ API
- ตั้งค่าพื้นฐานที่จำเป็น เช่น จุดเตือนสต็อกต่ำ และข้อมูลบัญชีผู้ใช้งาน
- มีระบบล็อกอินและการปกป้องข้อมูลลูกค้า; ยังไม่ต้องทำระบบสิทธิ์พนักงานหลายระดับ

## 3. ขั้นตอนการทำงานที่ต้องถูกต้อง

```text
รับออเดอร์จาก Marketplace (ผ่าน API เมื่อได้รับสิทธิ์ / ใช้ข้อมูลทดสอบก่อน)
    ↓
จับคู่ SKU ของ Marketplace กับ SKU ภายใน
    ↓
จองจำนวนสินค้าของออเดอร์ที่ต้องจัดส่ง
    ↓
รับ/เปิด/พิมพ์ใบปะหน้าจากช่องทางที่รองรับ
    ↓
สแกนบาร์โค้ดใบปะหน้า → ระบบเปิดออเดอร์ที่ตรงกัน
    ↓
ตรวจ SKU และจำนวนสินค้า (อาจสแกน Data Matrix)
    ↓
ยืนยันแพ็กสำเร็จ → ตัดสต็อกจริงเพียงครั้งเดียว
    ↓
บันทึกประวัติ และแสดงสถานะการส่งที่เชื่อมต่อได้จริง
```

**กติกาบังคับ**
- เมื่อจอง: เพิ่ม `Reserved` แต่ยังไม่ลด `On-hand`; คำนวณ `Available = On-hand - Reserved`
- เมื่อยืนยันแพ็ก: ลด `On-hand` และปลด `Reserved` ส่วนที่เกี่ยวข้อง **เพียงครั้งเดียว**
- การซิงก์ออเดอร์ซ้ำหรือสแกนซ้ำต้องไม่จองหรือตัดสต็อกซ้ำ
- การยกเลิกก่อนแพ็กให้ปลดยอดจอง; หลังตัดสต็อกแล้วหรือกรณีคืนสินค้า ต้องตรวจเงื่อนไขและบันทึกรายการปรับยอดอย่างเหมาะสม
- **ห้ามตัดสต็อกเพียงเพราะสแกนใบปะหน้า** ต้องค้นหาออเดอร์ถูกต้องและยืนยันแพ็กก่อน
- หากสแกนไม่พบออเดอร์ / ผิด SKU / จำนวนไม่ครบ ต้องแจ้งเตือนชัดเจนและไม่ยืนยันรายการ
- ไม่อนุมานว่าสถานะใน Marketplace เปลี่ยนแล้ว หากยังไม่ได้รับผลการอัปเดตจริง

## 4. ข้อมูลและรหัสที่ต้องใช้
เก็บเฉพาะข้อมูลจำเป็นต่อการทำงาน ไม่ต้องกำหนดชื่อตารางหรือระบบฐานข้อมูลละเอียดในบรีฟนี้

| กลุ่มข้อมูล | สิ่งสำคัญ |
| --- | --- |
| สินค้า | ชื่อ, SKU ภายใน, ตัวเลือก, SKU ของ Marketplace, รหัส Data Matrix |
| สต็อก | On-hand, Reserved, Available, ประวัติรับเข้า/ตัดออก/ปรับยอด |
| ออเดอร์ | แพลตฟอร์ม, เลขออเดอร์, วันที่, รายการ SKU, จำนวน, สถานะ, ผู้สั่ง/ผู้รับเท่าที่ได้รับสิทธิ์ |
| พัสดุ | เลขติดตาม/รหัสจากใบปะหน้า, ออเดอร์ที่ผูกอยู่, สถานะแพ็ก/ขนส่ง |
| ประวัติ | เหตุการณ์, วันเวลา, ผลการดำเนินการ และผู้ดำเนินการเมื่อมีข้อมูล |

**Data Matrix บน Packaging**
- ใช้ **Data Matrix ECC200** เป็นทางเลือกสำหรับรหัส SKU ภายใน ไม่ใช่บาร์โค้ดขายหน้าร้าน
- เก็บเพียง SKU/รหัสสินค้า **ไม่เก็บข้อมูลลูกค้า สต็อก หรือความลับของร้านไว้ในโค้ด**
- คนทั่วไปที่มีเครื่องสแกนรองรับสามารถอ่านรหัสในโค้ดได้ แต่ข้อมูลหลังบ้านต้องล็อกอินจึงเข้าถึงได้
- ต้องทดสอบว่าเครื่องสแกนรุ่นที่เลือกอ่าน Data Matrix ได้จริง และงานพิมพ์มีขนาด/ความคมชัด/พื้นที่ว่างรอบโค้ดเพียงพอ
- **บาร์โค้ดใบปะหน้าไม่ใช่ SKU เสมอไป** ต้องมีการผูกรหัสที่อ่านได้เข้ากับออเดอร์ในระบบ และทดสอบกับใบปะหน้าจริง

## 5. การเชื่อม Marketplace และข้อจำกัด
- เป้าหมายคือ **ดึงออเดอร์อัตโนมัติจาก Shopee, Lazada และ TikTok Shop ผ่าน API** เมื่อได้รับอนุญาต
- ตอนนี้ยังไม่มีร้าน/สิทธิ์เชื่อมต่อที่ยืนยันแล้ว: ให้ทำระบบหลักและทดสอบด้วย **ออเดอร์ตัวอย่าง** ก่อนได้
- ถ้าจำเป็น สามารถเตรียมช่องทาง **นำเข้าไฟล์ออเดอร์** เป็นทางเลือกชั่วคราว โดยตรวจสอบรูปแบบไฟล์จริงก่อน
- ต้องตรวจสอบเอกสารและสิทธิ์ของ API แต่ละแพลตฟอร์มก่อนทำส่วนดึงข้อมูลลูกค้า พิมพ์ใบปะหน้า ซิงก์สถานะ และซิงก์สต็อก
- ไม่เขียนหน้า UI หรือข้อความที่ทำให้เข้าใจว่าซิงก์อัตโนมัติสำเร็จแล้ว หากยังไม่ได้เชื่อมและทดสอบจริง
- ข้อมูลลูกค้าใช้เท่าที่จำเป็น จำกัดการเข้าถึงตามสิทธิ์และข้อกำหนดของแพลตฟอร์ม/PDPA; เก็บคีย์ API ฝั่งเซิร์ฟเวอร์และไม่แสดงในหน้าเว็บ

## 6. คำสั่งให้ Claude
1. เริ่มจากเสนอ **โครงสร้างหน้าเว็บ 3 เมนู + Settings** พร้อมการจัดวางฟังก์ชันย่อย โดยไม่แยกเมนูหลักเพิ่ม
2. แสดง **User Flow การจัดการออเดอร์และแพ็กสินค้า** ให้เห็นว่าพนักงานกด/สแกนอะไรในแต่ละขั้นตอน
3. ออกแบบ UI เรียบง่ายสำหรับคอมพิวเตอร์เป็นหลัก เน้นค้นหาออเดอร์เร็ว ปุ่มทำงานชัดเจน และใช้เครื่องสแกนแบบพิมพ์ข้อความลงช่องได้
4. แยกให้ชัดว่าอะไร **ทำงานได้แล้วด้วยข้อมูลทดสอบ** และอะไร **รอ API/สิทธิ์/เครื่องสแกนจริง**
5. ถ้าข้อมูลสำคัญยังไม่ชัด **ให้ถามก่อนพัฒนา ห้ามเดา** โดยเฉพาะคำถามเหล่านี้:
   - ในขั้นแพ็ก ต้องสแกน Data Matrix ของสินค้าทุกชิ้น หรือแค่สแกนใบปะหน้าแล้วตรวจ/ยืนยันรายการ?
   - จะใช้ Data Matrix เดียวกันสำหรับสินค้าทุกชิ้นที่เป็น SKU เดียวกันใช่หรือไม่?
   - เมื่อเปิดร้านจริง จะเชื่อม API และพิมพ์ใบปะหน้าผ่านช่องทางใดได้บ้าง?
6. **ห้ามเพิ่ม** POS, CRM การตลาด, ระบบบัญชี, กราฟ/รายงานขั้นสูง, ระบบล็อต/วันหมดอายุ หรือฟังก์ชันอื่นที่ยังไม่ได้อนุมัติ

**เป้าหมายสุดท้าย:** เว็บหลังบ้านที่ใช้งานง่าย แต่ติดตามได้ครบว่าออเดอร์ไหนสั่งอะไรจากช่องทางใด ต้องแพ็กอะไร ส่งให้ใคร สต็อกเหลือเท่าไร และเกิดรายการรับเข้า/จอง/ตัด/คืนเมื่อใด โดยไม่ทำงานซ้ำหลายหน้า
